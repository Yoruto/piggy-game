# v1.0 Web View 接入验收记录（UI Beta）

> **目标**：原生 HTML/CSS/JavaScript 表现层；设计基线为 Demo v1.0 与 Architecture v1.0（MVP + Config）。  
> **版本状态**：UI 已接入并通过本轮工程测试；**v1.3 正式战斗数值仍未验收**。

## 交付范围

- 主菜单：开始/继续挑战、背包、内存重置、四只冒险伙伴预览。
- 战斗 View：原创 SVG 猪猪形象、草地战斗场景、双方 HP/SP、6 个技能位、技能属性、SP/威力、防御、普通换人、强制换人、1 More、Baton Pass、状态和减益标记、已知抗性槽、战斗日志。
- 背包 View：8 格容量、猪实例详情、四只出战队伍选择、技能位、技能卡填入/替换、升级学习测试入口。
- 胜负结算 View：对局结果、战利品技能卡、从三只敌猪中选择一只收编/放弃、满包处理；失败后返回营地。
- 运行时：无第三方前端框架或素材依赖、响应式手机/桌面、ES Modules + 静态 HTTP Server；不保存到本地存储。

## 自动化验收

```bash
npm test
npm run check:architecture
npm run validate:config
npm run test:fixtures
npm run test:headless
npm run smoke:headless
```

- 原有 Domain / Application / Presenter Node 用例保持通过。
- WebBattlePort 的玩家命令→敌方行动续跑契约、重复点击修订号拒绝、原创图形格式化等 Node 用例通过。
- 静态 HTTP 返回 HTML、JS、CSS、JSON 路由均为 200，未知资源为 404。
- 结构、命令、事件、隐藏抗性数据权限保持不变，View 不计算技能伤害。

## 尚未完成 / 风险

1. **数值未正式验收**：伤害计算、松软发酵参数、抗性抽取、接棒倍率等依旧使用明确标记的 Demo Fixture。正式 v1.3 配置入库后须重跑规则与视觉验收。
2. **素材策略**：此版本用 CSS 和原创 SVG 绘制猪猪。没有使用宝可梦角色、名称、素材或截图，只参考回合制 RPG 的信息层次与交互体验。
3. **完整 UI 自动化**：真实 HTTP 加载的浏览器 E2E / 多浏览器兼容尚需在可访问本地服务器的 CI 或开发机上补充。本轮浏览器内存加载冒烟不作为跨浏览器保证。
4. **极端交互**：建议进一步覆盖背包满的收编弹窗、全部技能位占满替换、所有猪阵亡和超长日志可访问性等端到端场景。

## 结论

Web View 完成可操作的 UI Beta，对应 v1.0 版本计划的表现层实施阶段。保持 Domain / Application / Presenter / Config 分离；正式产品发布仍以完整战斗系统 v1.3 数值验收和真实部署 E2E 为条件。
